## 1. Required domain and the meaning of resource bounds

The [Java25 BigInteger public API](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/math/BigInteger.html), class description24–33, requires every integer strictly between −2^L and +2^L, L=2147483647, and allows wider implementations. Own support chooses that range; out-of-support generated values use AE. Negative shift distances and infinite signed bits remain meaningful. Probable-prime values may have a smaller envelope, at least through2^500000000. Complexity and intermediate allocation can be large; this is not a fixed-heap/time guarantee. Neither a guessed smaller bit limit nor a timeout proves a required integer unsupported.

The [Java25 BigDecimal public API](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/math/BigDecimal.html), class description15–49, defines integer coefficient and signed32-bit scale, exact/unlimited arithmetic, precision/rounding and operation-specific cohorts. Nonzero inexact ordinary results retain requested precision, including trailing coefficient zeros. Exact results follow the relevant preferred-cohort rule. A result-scale overflow can permit AE; mere numerical equivalence to some other cohort does not settle the required representation. The complexity note66–71 acknowledges output/temporary size. This permission does not generally excuse an avoidable unsupported numerical intermediate when a required coefficient/scale is supported. The separately qualified working-scale/LOW/HIGH policies below are retained, not generalized.

Reuse the accepted566/528 magnitude certificate: K=646456992, H=K+1=646456993; every supported coefficient has at mostH decimal digits,10^K is supported,10^H is not.
